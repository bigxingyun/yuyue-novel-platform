## 1. 应用入口与装配

`backend/app/main.py` 装配顺序：

1. 定义 `AuthRateLimitMiddleware`：`/api/v1/auth/*` 每 IP 每分钟 30 次，超限返回 429 `{ code: 429, message: "请求过于频繁" }`（内存 `defaultdict` 滑动窗口）。
2. `lifespan`：启动时调用 `init_db()`（建表 + 可选种子）。
3. 创建 `FastAPI(title="欲阅 API", version="0.1.0")`：生产环境关闭 `/docs`、`/redoc`。
4. `register_exception_handlers(app)` 注册全局异常处理器。
5. 挂中间件：限流 → CORS（`settings.cors_origins` 白名单）。
6. `GET /health`：裸返回 `{"status": "ok"}`（运维探活，不走 ApiResponse）。
7. `include_router(api_v1_router, prefix="/api/v1")`。
8. 挂载 `/uploads` 静态目录（`settings.upload_dir`）。
9. `mount_frontend(app)`：生产单端口模式下托管 `frontend/dist`（`/assets` 静态 + `/{spa_path:path}` SPA 回退；`api/`、`uploads/` 前缀拒绝回退，防路径穿越校验）。

## 3. 数据库与会话

`app/database.py`：

| 项 | 实现 |
|----|------|
| 引擎 | `create_engine(settings.database_url)`；SQLite 加 `check_same_thread: False` |
| 会话 | `SessionLocal = sessionmaker(autocommit=False, autoflush=False)`；`get_db()` 依赖注入 |
| 建表 | `seed.init_db()`：`Base.metadata.create_all` + `run_schema_migrations` |
| 增量补丁 | `run_schema_migrations()`：建 `schema_migrations` 版本表；v1 补 `users.reader_settings`、`books.admin_delisted` 列 |

时间约定（`utils/datetime_util.py`）：库内 UTC naive（`now_utc()`）；展示接口转东八区 `Asia/Shanghai` 格式化（`format_display_datetime/date`）。

## 4. 认证与鉴权

`app/core/security.py`：

- 密码：`passlib` CryptContext（bcrypt）`hash_password` / `verify_password`。
- JWT：`python-jose`，HS256；载荷 `{ sub, type, exp }`；`create_access_token` / `create_refresh_token`；`decode_token(token, expected_type)` 校验类型，失败抛 `40101 TOKEN_EXPIRED`；`try_decode_token` 容错版。

`app/api/deps.py` 鉴权依赖：

| 依赖 | 规则 |
|------|------|
| `get_current_user` | Bearer → 解 token → 查库 → 封禁检查 → 返回 User；缺失/无效抛 `401` |
| `get_current_user_optional` | 同上但允许匿名（公开读接口用，如 `GET /books/{id}`） |
| `require_author` | 角色 ∈ {author, admin, superadmin}，否则 `40302` |
| `require_admin` | 角色 ∈ {admin, superadmin}，否则 `40303` |
| `require_superadmin` | 仅 superadmin，否则 `40303`（提示超管） |
| `require_roles(*roles)` | 工厂（预留未用） |
| `get_pagination` → `Pagination` | `page>=1`、`1<=page_size<=50`，非法抛 `400` |

**账号封禁**：`_user_from_token` 在查库后检查 `status == banned`，抛 `40301 ACCOUNT_BANNED`——已登录被封用户下一次请求即被登出。

## 5. 异常处理

`app/core/exceptions.py`：

- `AppException(code, message=None, http_status=None, data=None)`：仅 Service 层抛出；`raise_app()` 简写。
- `http_status_for_code(code)`：业务 code → HTTP 状态映射（0→200；40101→401；40301/40302/40303→403；40401/40402→404；40901/40002→409；40001→400；500→500）。
- 全局处理器（`register_exception_handlers`）：
  - `AppException` → 对应 HTTP 状态 + `{ code, message, data: null }`；
  - `RequestValidationError` → `422` + `code: 400` + 拼接前 3 条校验错误；
  - `StarletteHTTPException` → 状态映射（401/403/404/409）或 400；
  - 未捕获 `Exception` → `logger.exception` 记录 + `500` 通用文案。

前端配套：`http.ts` 拦截器归一为 `AppError`；`40101` 单飞刷新重放；失败 `invalidateSession()`（详见 [07-前端实现.md](./07-前端实现.md)）。

## 6. 业务模块实现

### 6.1 认证 `auth_service.py`

| 函数 | 关键逻辑 |
|------|----------|
| `login` | 昵称或 ID 查用户（`_find_user_by_account`：先昵称后数字 ID）；密码错误与用户不存在同文案「账号或密码错误」防枚举；封禁拒绝 |
| `refresh` | 解 refresh token → 查用户 → 封禁检查 → 签发新双 token |
| `verify_registration_key` | 大写化 → 查 unused → 过期则标记 expired 并抛 `40001` |
| `register` | 校验注册码 → 昵称规范化 + 唯一性（`assert_nickname_available`）→ 建用户 → **CAS 原子消费注册码**（`UPDATE ... WHERE status=unused`，rowcount≠1 则 rollback 抛 `40001`）→ commit（IntegrityError 兜底昵称占用）→ 返回双 token 自动登录 |
| `recover_password` | 账号 + 找回密钥（绑定 user_id）→ 未用未过期 → CAS 消费 → 重置密码 |

### 6.2 用户与个人中心 `profile_service.py`

| 函数 | 关键逻辑 |
|------|----------|
| `get_user_out` | 组装 UserOut（含 level/title/exp_in_level/exp_to_next，来自 `title_service`） |
| `update_profile` | 部分更新：昵称非 None 且变化时才校验唯一性（排除自身）；avatar 非 None 才写 |
| `change_password` | 校验旧密码 → 重哈希 |
| `check_in` | 今日唯一（先查后插 + IntegrityError 兜底）；随机运势（`data/fortunes.py`）+ 随机经验 5–15；写 `check_ins` + `exp_logs` + `user.exp`；返回 `leveled_up` / `new_title`（跨级晋升提示） |
| `check_in_status` | 查今日记录 |
| `list_exp_logs` | 分页 + source 中文映射（签到/阅读/评论） |
| `get_titles` | 当前头衔信息 + 全部 10 级解锁状态 |
| `submit_author_application` | 存在 pending 申请则 `409` 冲突 |
| `get_author_application` | 取最近一条申请 |
| `get/update_reader_settings` | 读取/写入 `users.reader_settings` JSON 文本 |

### 6.3 书籍 `book_service.py`

| 函数 | 关键逻辑 |
|------|----------|
| `list_books` | 只查 `status=published`；分类过滤（`全部`/空忽略）；关键词 `title ilike` 或作者昵称 `ilike`；排序 `updated`（默认，`updated_at desc`）/ `words`（`word_count desc`）；分页 |
| `get_book_detail` | 只查 published；带 `chapters`（按 sort_order 排序）与 `author`；登录用户附带 `progress`、`in_shelf` |
| `get_chapter` | 查章节 → 校验所属书 published；返回 `content` + `paragraphs`（文本段）+ `blocks`（text/image） |
| `list_update_logs` | 按更新时间倒序，join 章节标题 |
| `list_book_comments` / `create_book_comment` | **已废弃**（Deprecated），路由已迁移到 `comment_service` |

### 6.4 评论 `comment_service.py`

三级评论统一模型：

| 类型 | 锚点 | 表 |
|------|------|-----|
| paragraph | `chapter_id + paragraph_index` | `paragraph_comments` |
| chapter | `chapter_id` | `chapter_comments` |
| book | `book_id` | `book_comments` |

| 函数 | 关键逻辑 |
|------|----------|
| 列表查询 | 过滤 `is_hidden=false`；排序 `is_pinned desc, created_at asc`（置顶优先再时间倒序）；`_build_tree` 按 `parent_id` 组装一层回复 |
| 发表 | 校验所属书/章已发布；`_validate_parent`：父评论必须同锚点、仅支持一级回复（父有 parent_id 则拒绝）；写评论 + `award_comment_exp`（同事务）；commit |
| `list_paragraph_comments_by_chapter` | 整章段评按 `paragraph_index` 分组返回（阅读页一次性拉取） |
| `delete_comment` | 权限：本人 / 管理员 / 本书作者（`_can_manage_comment`）；删除时级联删除其一级回复 |
| `pin_comment` | 权限：本书作者 / 管理员；置顶前把同锚点其他置顶取消（互斥，每段/每章至多一条） |
| `hide_comment` / `unhide_comment` | 管理端按 type 切换 `is_hidden` |

评论出参（`CommentOut`）含 `avatar`、`level`、`title`（`_user_comment_fields` 由经验头衔计算），供前端展示头像与徽章。

### 6.5 书架 `bookshelf_service.py`

- `list_bookshelf`：join 已发布书；每条附进度（`chapter_id`、`chapter_title`、`progress` 百分比、`read_at`）；按 `read_at` 倒序（最近阅读优先）。
- `add_to_bookshelf`：已存在幂等返回；书籍非 published 拒绝。
- `remove_from_bookshelf`：存在则删除。

### 6.6 阅读 `reading_service.py`

- `get_progress`：查 `(user_id, book_id)` 唯一进度。
- `update_progress`：校验书已发布、章节属于该书；存在则更新 `chapter_id/offset/updated_at`，否则新建；**每次上报追加一条 `reading_history`**；章节变化时 `award_read_exp`（同事务）；commit。
- `list_history`：join 书与章节，只显示已发布书，按时间倒序分页。

### 6.7 作者 `author_service.py`

| 函数 | 关键逻辑 |
|------|----------|
| `list_author_books` / `_get_owned_book` | 只返回本人作品（越权返回 `40401` 而非 403，防探测） |
| `create_book` | 分类白名单（`BOOK_CATEGORIES`，非法回落「其他」）；默认封面 picsum；状态 `draft` |
| `update_book` | 部分更新（title/description/category/cover 非 None 才写） |
| `create_chapter` | `validate_chapter_content`（图片外链拒绝）→ `normalize_chapter_content`（规范 marker）→ 统计字数（去空白）→ `sort_order = max+1` → 回写书籍 `word_count` → 已发布则写 `update_logs` |
| `update_chapter` | 部分更新；字数变化时 `added = max(0, new-old)` 记日志 |
| `delete_chapter` | 删除并回写书籍字数 |
| `reorder_chapters` | 传入完整 id 列表（集合必须相等），按序重写 `sort_order` |
| `publish_book` | 管理员下架后禁止自行重新上架（`admin_delisted`）；至少一章才能发布；首次发布写最新章 update_log |
| `unpublish_book` | 管理员下架后禁止；仅 published 可下架 |
| `delete_book` | **仅草稿状态可删除** |

### 6.8 管理 `admin_service.py`

| 函数 | 关键逻辑 |
|------|----------|
| `list_users` | 关键词：数字可匹配 ID 或昵称模糊；按创建时间倒序 |
| `update_user_status` | 不能封禁自己；普通管理员不能改管理员账号 |
| `update_user_role` | 仅超管；不能改管理员/超管角色（防提权）；授予管理员仅超管 |
| `generate_registration_keys` | 批量生成 `YUYUE-{hex8}`（`secrets.token_hex`）；可选有效期 |
| `list_registration_keys` | 分页；过期未用动态标 `expired` |
| `generate_recovery_key` | 先作废该用户所有未用密钥，再生成 `RCV-{hex8}` 7 天有效 |
| `list_admin_books` | 全站书籍分页 |
| `update_admin_book_status` | 下架 = `unpublished` + `admin_delisted=true`；上架 = `published` + `admin_delisted=false`（至少一章） |
| `delete_admin_book` | **级联清理**：段评/章评/书评/更新日志/进度/历史/书架/章节 → 删书 |
| `list_applications` / `review_application` | 审核用 CAS（`status=pending` 才能更新，否则 `409` 已处理）；通过且用户为 user → 角色改 author |

| `hide/unhide_admin_comment` | 委托 `comment_service` |
| `list/get/update_admin_chapter` | 后台章节编辑，复用 `validate/normalize_chapter_content`，回写字数 |

### 6.9 经验 `exp_service.py`

| 项 | 值 |
|----|----|
| 阅读经验 | 2/章，日上限 20（`READ_EXP_DAILY_CAP`），仅章节变化发放 |
| 评论经验 | 5/条，日上限 25（`COMMENT_EXP_DAILY_CAP`），回复也发 |
| 发放实现 | `award_exp`：`SELECT FOR UPDATE` 锁用户行防并发超发；`_today_exp_total` 按当日 `exp_logs` 汇总；`actual = min(amount, cap - earned)`；写 `exp_logs`；**不 commit，由调用方同事务提交** |

## 7. 正文块模型

`app/utils/chapter_content.py`：

- **存储真相**：`chapters.content` 是原始文本，按 `\n\n` 分段；整行 `[img:...]` 为图片块 marker。
- `parse_chapter_blocks(content)` → `[{type: "text", text, paragraph_index} | {type: "image", url, after_paragraph_index}]`。`paragraph_index` 只对文本段递增（**图片块不占段落索引**），`after_paragraph_index` 表示图片插在哪个文本段之后。
- `normalize_image_url(url)`：`/uploads/...` 直接通过；`http(s)://.../uploads/...` 提取路径；其他抛 `ValueError`（拒绝外链）。
- `normalize_chapter_content(content)`：重写所有 marker 为规范相对路径（历史脏数据修复）。
- `validate_chapter_content(content)`：校验所有图片 marker 必须为本站 `/uploads/` 路径，否则 `400`「图片地址无效」。
- 字数统计：`len(content.replace("\n","").replace(" ",""))`。

## 8. 经验与头衔

`app/services/title_service.py`：

- `TITLE_LEVELS`（`core/constants.py`）：10 级，门槛 0 / 30 / 80 / 150 / 250 / 400 / 600 / 900 / 1300 / 1800。
- `get_title_info(exp)`：按 `min_exp` 取最高档；计算 `exp_in_level`、`exp_to_next`、`progress`。
- `list_all_titles(exp)`：全部头衔 + `unlocked` / `current` 状态。
- 头衔**由经验实时计算**，无独立 DB 字段，与权限 `role` 正交。

## 9. 文件上传

`app/services/upload_service.py`：

| 项 | 值 |
|----|----|
| MIME 白名单 | `image/jpeg, png, webp, gif` |

## 10. 初始化与种子数据

| 入口 | 行为 |
|------|------|
