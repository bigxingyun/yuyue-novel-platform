## 1. 测试体系概览

| 层 | 框架 | 位置 | 覆盖 |
|----|------|------|------|
| 后端单元/集成 | pytest | `backend/tests/` | 认证密钥、签到、资料修改、管理功能、正文解析 |
| 前端单元 | Vitest | `frontend/src/utils/parseChapterBlocks.test.ts` | 正文块解析 |
| 手工功能验证 | 黑盒 | — | 全功能主链路（登录、阅读、评论、创作、后台） |

类型以黑盒功能测试为主，辅以后端自动化用例（针对核心业务规则与权限边界）。

## 2. 运行方式

### 2.1 后端

```bash
cd backend
pip install pytest httpx        # 注意：requirements.txt 不含测试依赖，需另行安装
python -m pytest tests/ -v
```

> FastAPI `TestClient` 依赖 `httpx`；测试直接使用默认开发数据库（`sqlite:///./yuyue.db`），无独立测试库，用例内手动清理数据（`uuid` 唯一命名 + try/finally 删除）。

### 2.2 前端

```bash
cd frontend
npm test                        # vitest run
```

配置在 `vite.config.ts`：`environment: 'node'`、`include: ['src/**/*.test.ts']`。

## 3. 后端测试用例

### 3.1 `test_auth_keys.py` — 注册码原子消费

| 用例 | 验证点 |
|------|--------|
| `test_registration_key_cannot_be_used_twice` | 同一注册码二次注册抛 `40001 REGISTRATION_KEY_INVALID`；CAS 原子消费不重复建号 |

### 3.2 `test_check_in.py` — 签到

| 用例 | 验证点 |
|------|--------|
| `test_duplicate_check_in_returns_conflict` | 同日重复签到抛 `40901 ALREADY_CHECKED_IN` |

### 3.3 `test_profile.py` — 资料修改

| 用例 | 验证点 |
|------|--------|
| `test_update_avatar_only_keeps_nickname` | PATCH `/users/me` 仅改头像时昵称不变（部分更新不误判唯一性占用） |
| `test_update_profile_service_avatar_only` | Service 层同规则纯逻辑验证 |

### 3.4 `test_admin_features.py` — 管理功能

| 用例 | 验证点 |
|------|--------|
| `test_recover_password_with_valid_key` | 生成找回密钥 → 重置密码 → 密钥置 used → 新密码可登录 |
| `test_admin_republish_blocks_author_until_admin_approves` | 管理员下架（`admin_delisted=true`）后作者不可上下架；管理员恢复后作者可重新发布 |
| `test_unhide_comment` | 评论隐藏后 `is_hidden=true`；恢复后 `is_hidden=false` |

### 3.5 `test_chapter_content.py` — 正文块解析

| 用例 | 验证点 |
|------|--------|
| `test_parse_text_and_image_blocks` | `\n\n` 分段 + `[img:...]` 识别；`paragraph_index` 只计文本段；`after_paragraph_index` 正确 |
| `test_normalize_legacy_localhost_upload_url` | 旧 `http://127.0.0.1:5173/uploads/...` 归一为 `/uploads/...` |
| `test_parse_content_with_legacy_http_marker` | 旧版绝对 URL marker 解析归一 |
| `test_reject_external_url_in_marker` | 外链图片 marker 抛 `400 BAD_REQUEST`（防注入/盗链） |
| `test_normalize_valid_marker` | 合法 marker 规范化后校验通过 |

## 4. 前端测试

`frontend/src/utils/parseChapterBlocks.test.ts`（vitest）：验证 `parseChapterBlocks` 对文本/图片块的解析、`insertImageAfterParagraph`、`removeImageAt` 等纯函数（与后端 `chapter_content` 行为一致）。

## 5. 测试基础设施

`backend/tests/conftest.py`：唯一 fixture `apply_schema_migrations`（session 级、autouse），测试运行前执行 `run_schema_migrations(engine)`，保证 `reader_settings`、`admin_delisted` 等增量列就绪。

> 说明：当前没有独立的测试数据库/事务回滚隔离，测试与开发共用 `yuyue.db`；每个用例自行创建并清理数据。新增用例请沿用该模式（唯一命名 + finally 清理）。

## 6. 覆盖情况与缺口

### 6.1 已覆盖

- 注册码一次性语义（核心准入规则）
- 签到每日一次（核心成长规则）
- 资料部分更新（昵称占用误判回归）
- 找回密码流程、管理员下架与作者重新上架边界、评论隐藏恢复
- 正文块解析与图片 URL 安全（核心内容模型）

### 6.2 缺口（建议补充）

| 缺口 | 建议 |
|------|------|
| 前端组件/页面测试 | 引入 @vue/test-utils，覆盖评论权限、阅读设置、守卫跳转 |
| API 集成测试不足 | 用 TestClient 覆盖登录 → 阅读 → 评论 → 创作的完整链路 |
| 端到端测试 | Playwright/Cypress 走通核心用户旅程 |
| 性能基准 | 章节切换 < 500ms、API P95 < 300ms 的压测脚本 |
| 安全专项 | 越权矩阵（user 访问 admin 端点）、上传恶意文件、JWT 篡改 |

> 测试缺口对应的规划见 [11-未完成需求与规划.md §6](./11-未完成需求与规划.md)。
