## 1. 命名规则

### 1.1 各层级风格

| 层级 | 风格 | 示例 |
|------|------|------|
| 数据库 | `snake_case`，表名复数 | `users`, `reading_progress` |
| API 路径 | `kebab-case`，复数资源 | `/api/v1/books`, `/update-logs` |
| API JSON 载荷 | `snake_case` | `book_id`, `access_token` |
| Python 代码 | `snake_case`；类 `PascalCase` | `book_service.py`, `UserRole` |
| TypeScript 逻辑 | `camelCase`；类型 `PascalCase` | `bookId`, `UserInfo` |
| Vue 组件文件 | `PascalCase.vue` | `BookCard.vue`, `ReaderView.vue` |
| 路由 path / name | `kebab-case` | `/profile/apply-author`, `profile-edit` |
| 常量 | `UPPER_SNAKE_CASE` | `MAX_PAGE_SIZE` |
| 枚举值（存库/接口） | `snake_case` 小写字符串 | `user`, `published` |
| 环境变量 | `UPPER_SNAKE_CASE` | `DATABASE_URL` |
| Git 分支 | `kebab-case` | `feat/reader-settings` |

### 1.2 字段级命名

| 场景 | 命名 | 示例 |
|------|------|------|
| 外键字段 | `{实体}_id` | `user_id`, `author_id` |
| 布尔字段 | `is_` / `has_` 前缀 | `is_pinned`, `has_checked_in` |
| 时间字段 | `_at` 后缀 | `created_at`, `updated_at`, `used_at` |

### 1.3 文件与模块命名

#### 后端 `backend/app/`

| 类型 | 规则 | 示例 |
|------|------|------|
| 模型 | `models/{单数}.py`，类名 PascalCase 单数 | `models/book.py` → `class Book` |
| Schema | `schemas/{模块}.py` | `BookCreate`, `BookOut` |
| 路由 | `api/v1/{模块}.py` → `APIRouter(prefix="/books")` | `books.py` |
| 服务 | `services/{模块}_service.py` | `book_service.py` → `get_book_by_id()` |
| 测试 | `tests/test_{模块}.py` | `test_auth.py` |

#### 前端 `frontend/src/`

| 类型 | 规则 | 示例 |
|------|------|------|
| 页面 | `views/{域}/{Name}View.vue` | `views/reader/ReaderView.vue` |
| 布局 | `layouts/{Name}Layout.vue` | `DefaultLayout.vue` |
| 组件 | `components/{域}/{Name}.vue` | `components/comment/CommentDock.vue` |
| API 模块 | `api/{模块}.ts`，函数动词开头 | `fetchBookList()`, `createBookComment()` |
| Store | `stores/{名}.ts` → `use{Name}Store` | `stores/user.ts` → `useUserStore` |
| Composable | `composables/use{Name}.ts` | `useReader.ts`, `useScrollLock.ts` |
| 类型 | `types/{域}.ts` | `types/book.ts` → `interface Book` |

## 2. 前后端字段映射

**边界规则**：网络传输与持久化一律 `snake_case`；前端业务代码一律 `camelCase`。转换仅在 API 层发生。

```
数据库 snake_case ←→ API JSON snake_case ←→ [http.ts 转换层] ←→ 前端 camelCase
```

| 数据库 / API | 前端 |
|--------------|------|
| `book_id` | `bookId` |
| `chapter_id` | `chapterId` |
| `created_at` | `createdAt` |
| `word_count` | `wordCount` |
| `access_token` | `accessToken` |

实现位置：

- 前端：`frontend/src/utils/caseTransform.ts`（`keysToSnake` / `keysToCamel`），仅由 `api/http.ts` 调用。
- 后端：Pydantic 默认 `snake_case`，不输出 camelCase。

## 3. 分层与禁止越层

### 3.1 后端

| 层级 | 允许 | 禁止 |
|------|------|------|
| `api/v1/` 路由 | 鉴权、校验、调 Service、`ok()` 包装 | SQL、复杂分支 |
| `services/` | 业务规则、事务（同一方法内提交） | 依赖 `Request` / `Response` |
| `models/` | 表结构、关系 | 业务判断 |

### 3.2 前端

| 层级 | 允许 | 禁止 |
|------|------|------|
| `views/` | 组合组件、绑定 Store、调 composable | 直接 HTTP；复杂业务计算 |
| `composables/` | 封装可复用逻辑、调 api | 操作 DOM（除非 reader 专用） |
| `api/` | 封装请求路径与类型 | 持有 UI 状态 |
| `stores/` | 全局用户态、设备态、阅读设置 | 替代 Service 做业务校验 |

## 4. 响应协议

**成功：**

```json
{ "code": 0, "message": "ok", "data": {} }
```

**失败：**

```json
{ "code": 40001, "message": "注册码无效", "data": null }
```

**分页 `data`（固定结构）：**

```json
{ "items": [], "total": 0, "page": 1, "page_size": 20 }
```

| 字段 | 类型 | 规则 |
|------|------|------|
| `code` | int | `0` 成功；`4xx` HTTP 语义；`40001+` 业务错误 |
| `message` | string | 人类可读，前端可直接 Toast |
| `data` | object \| array \| null | 成功时有值；失败为 `null` |

> 例外：`/health` 返回裸 `{"status": "ok"}`（运维探活，不走 ApiResponse）。

## 5. 错误码与异常

### 5.1 错误码分段

| 区间 | 含义 |
|------|------|
| `0` | 成功 |
| `400` / `422` | 请求参数错误 |
| `401` | 未认证 |
| `403` | 无权限 |
| `404` | 资源不存在 |
| `409` | 冲突 |
| `500` | 服务器错误 |
| `40001–40099` | 认证业务（`40001` 注册码无效、`40002` 昵称已存在） |
| `40101–40199` | Token 业务（`40101` Token 过期） |
| `40301–40399` | 权限业务（`40301` 封禁、`40302` 需作者、`40303` 需管理员） |
| `40401–40499` | 资源业务（`40401` 书籍不存在、`40402` 章节不存在） |
| `40901–40999` | 冲突业务（`40901` 今日已签到） |
| `-1` | 前端网络错误（仅前端） |

### 5.2 后端抛出规则

```python
# Service 层
from app.core.exceptions import raise_app
from app.core.constants import ErrorCode

raise_app(ErrorCode.BOOK_NOT_FOUND)
raise_app(ErrorCode.NICKNAME_TAKEN, "该昵称不可用")
```

| 规则 | 说明 |
|------|------|
| 仅 Service 抛 `AppException` | 路由层不抛业务异常 |
| 禁止裸 `HTTPException` 表达业务错误 | 统一 `AppException`，全局处理器转响应 |
| `message` 用户可见 | 不写堆栈、SQL、内部路径 |
| 未预期异常 | `logger.exception`，对外返回 `500` + 通用文案 |

### 5.3 前端处理规则

```typescript
// 模式 A：useApiAction（推荐，带 loading）
const { loading, run } = useApiAction()
const data = await run(() => fetchBookList(), { silent: false })

// 模式 B：手动 catch + handleError
try {
  await createComment(payload)
} catch (error) {
  handleError(error) // 自动 Toast
}

// 模式 C：表单字段错误（silent + 手动绑定）
try {
  await register(form)
} catch (error) {
  const err = handleError(error, { silent: true })
  formErrors.nickname = err.message
}
```

| 规则 | 说明 |
|------|------|
| 禁止空 `catch (e) { console.log(e) }` | 必须 `handleError` 或向上抛 `AppError` |
| 禁止在 `http.ts` 外判断 axios 原始结构 | 统一 `AppError` / `isAppError()` |
| Token 过期 `40101` | 拦截器自动刷新一次；失败清 Token 由守卫跳登录 |
| 网络错误 | `code = -1` |
| 阅读页进度上报失败 | `silent: true`，本地队列重试 |

## 6. 枚举与常量单一来源

**禁止魔法字符串**，枚举/错误码/业务常量必须从单一来源引用：

| 来源 | 路径 |
|------|------|
| 后端枚举 / 错误码 | `backend/app/core/constants.py` |
| 前端枚举 | `frontend/src/types/enums.ts` |
| 前端 API 类型 | `frontend/src/types/api.ts` |

新增角色、状态、错误码流程：

1. 改 `constants.py` 与 `enums.ts`；
2. 两端 `DEFAULT_ERROR_MESSAGES`（后端 `core/exceptions.py`、前端 `utils/errorHandler.ts`）补文案；
3. 更新 [欲阅需求分析.md](../欲阅需求分析.md) 附录 D；
4. Service 中 `raise_app(ErrorCode.XXX)` 使用。
