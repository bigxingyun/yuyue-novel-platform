## 2. W01 广场字数区间筛选

### 2.1 需求

广场列表增加「字数区间」筛选：**< 1 万 / 1–5 万 / 5 万+**（与分类、排序、搜索正交）。

### 2.2 设计

**后端**（`book_service.list_books` 增加参数）：

```python
# 请求参数
word_count_range: str | None = None   # 取值 "lt_1w" | "1w_5w" | "gt_5w"

# 过滤逻辑（放在 category/keyword 之后）
RANGES = {
    "lt_1w":  lambda q: q.filter(Book.word_count < 10_000),
    "1w_5w": lambda q: q.filter(Book.word_count >= 10_000, Book.word_count <= 50_000),
    "gt_5w": lambda q: q.filter(Book.word_count > 50_000),
}
```

- 查询参数风格：`kebab-case` 不适用数值枚举，建议沿用 `snake_case` 值（与现有 `sort=words` 一致的小写风格）。
- `books.word_count` 已是冗余字段（章节增删改时回写），可直接过滤，无性能问题。

**前端**（`SquareView`）：

- 分类 chips 下方增加「字数」chips（全部 / <1 万 / 1–5 万 / 5 万+），单选、与分类/排序互不干扰；
- `fetchBookList` 增加 `wordCountRange` 参数透传；
- 空结果沿用 `EmptyState` 组件。

**接口变更**：`GET /books` 新增可选参数 `word_count_range`（不破坏现有调用）；同步更新 [欲阅需求分析.md](../欲阅需求分析.md) §7.3、§9.3 与 [08-API 接口文档.md](./08-API接口文档.md)。

## 3. W02 广场检索增强

### 3.1 需求

- 标签体系：书籍可打多个标签（如「治愈」「反转」「BE」），广场按标签筛选；
- 热度排序：按阅读量/评论量综合排序；
- 推荐位：首页运营推荐位（后台可配置）。

### 3.2 设计

| 项 | 方案 |
|----|------|
| 标签 | 新增 `tags`（VARCHAR, 逗号分隔或 JSON 数组）+ 可选 `book_tags` 关联表（多对多）；作者建书/编辑时可填 1–5 个标签；广场 `tag` 过滤用 `LIKE` 或关联表 JOIN |
| 热度 | `books` 增加冗余 `read_count` / `comment_count`（阅读进度上报与评论发表时 +1，参考 `word_count` 冗余模式）；排序 `sort=hot` 按综合权重 `read_count + comment_count*10` |
| 推荐位 | 新增 `recommendations` 表（`book_id`、`sort_order`、`enabled`）或复用 `books.is_recommended` 标记；后台作品页可勾选推荐；`GET /books?recommended=1` 返回推荐列表 |

**实现位置**：后端 `book_service` + `models/book.py` + `admin_service`；前端 `SquareView` + `WorksManageView`。

## 4. W03 内容安全与反垃圾

### 4.1 需求

- 敏感词过滤：评论/章节/昵称提交时检测；
- 反垃圾：同 IP/同账号高频发评限制、重复内容检测；
- 自动审核：可选先审后发或标记待审。

### 4.2 设计

| 层 | 方案 |
|----|------|
| 敏感词 | 维护敏感词表（DB 表 `sensitive_words` 或配置文件）；提交时在 Service 层扫描，命中返回 `400` + 提示；昵称注册时同样校验 |
| 频率限制 | 扩展 `AuthRateLimitMiddleware` 或新增评论专用限流（每用户每分钟 N 条，超限 `429`）；同内容短时间重复发表拒绝（内容哈希比对） |
| 审核模式 | `comments.*` 表增加 `review_status`（pass/pending/reject）或复用 `is_hidden` 语义；开启「先审后发」时新评论默认 `is_hidden=true` 进后台待审队列 |

**注意**：需新增错误码（如 `40003 SENSITIVE_CONTENT`、`40902 DUPLICATE_COMMENT`），按 [04-命名与实现规范.md](./04-命名与实现规范.md) §6 流程同步前后端常量与文档。

## 5. W04 对象存储与 CDN 迁移

### 5.1 需求

- 头像/封面/章节插图从本地 `uploads/` 迁移到对象存储（如阿里云 OSS / 腾讯云 COS / MinIO）；
- 静态资源走 CDN 加速。

### 5.2 设计

**接入点收敛**（现状已具备迁移条件）：

| 接入点 | 说明 |
|--------|------|
| `upload_service.save_image` | 唯一写入点：改为上传对象存储，返回完整 URL 或相对 key |
| `utils/mediaUrl.ts` `resolveMediaUrl` | 唯一展示解析点：按配置拼接 CDN 域名 |
| `main.py` `/uploads` 挂载 | 保留本地兼容；生产可切换为仅存对象存储 |

**方案**：

1. 配置新增 `STORAGE_BACKEND=local|oss|s3`、`STORAGE_ENDPOINT`、`STORAGE_BUCKET`、`CDN_BASE_URL`；
2. `upload_service` 按后端分支实现 `save_image`（本地 / 对象存储）；
3. 存量数据迁移脚本：遍历 `books.cover`、`users.avatar`、章节 `[img:...]` marker，上传对象存储并回写 URL；
4. 前端 `resolveMediaUrl`：`/uploads/...` 相对路径拼 `CDN_BASE_URL`，完整 URL 原样返回（当前逻辑已兼容）。

**回滚**：改回 `STORAGE_BACKEND=local` 即可，业务代码无感。

## 6. W05 数据库迁移 PostgreSQL

### 6.1 需求

- 用户量增长或需要更强并发/备份能力时迁移 PostgreSQL。

### 6.2 设计

| 项 | 方案 |
|----|------|
| ORM 层 | SQLAlchemy 已抽象差异，`DATABASE_URL` 改为 `postgresql+psycopg://...` 即可启动 |
| 待处理差异 | SQLite 特有：`check_same_thread`、`server_default=func.now()` 兼容、`BOOLEAN` 映射（PG 原生支持）；时间存储统一 UTC naive 已兼容 |
| 迁移工具 | 启用 Alembic（依赖已含 `alembic>=1.14.0`）：生成 baseline 迁移 + 现有 `run_schema_migrations` 增量补丁转为 Alembic revision |
| 数据迁移 | 停服 → pg_dump/自定义脚本导数据（`uploads/` 不迁移，仍走静态目录或 W04 对象存储） |
| 测试 | 增加 CI 矩阵：SQLite + PostgreSQL 双跑 pytest |
